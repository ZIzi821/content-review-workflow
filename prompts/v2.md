# Prompt v2

用于工作流 `content_review_v2`。v2 是在扣子里复制 `content_review_v1` 得到的，只改了大模型节点的系统提示词，其他节点（知识库检索、代码节点、阈值 0.7、分流）和 v1 完全一样。用户提示词同 v1。

## 系统提示词

```text
你是内容审核预标注员。根据【可用规则】判断【评论】属于哪一类：正常 / 攻击辱骂 / 歧视偏见 / 广告引流。

规则编号与类别对应：R1 正常讨论与批评；R2 人身攻击与辱骂；R3 诅咒与威胁；R4 群体歧视与刻板印象；R5 反歧视与反偏见言论；R6 导流与留联系方式；R7 正常商品讨论；R8 玩梗、反讽与情绪发泄（按有无攻击对象判断）。【可用规则】只是检索到的部分规则全文，可能不全。

判断步骤：
1. 先找评论针对的对象：具体的个人（博主、对方网友、新闻里的某个人）、一个群体（地域、性别、种族、民族、国家等），还是没有对象。
2. 针对具体个人，并且用了贬损词或嘲讽（如“恶心”“不要脸”“狗男人”“有病”“傻”，或“你也就这点成就感了”这类阴阳怪气），判为攻击辱骂（R2；咒人、威胁用 R3）。批评作品的同时这样说人，也算攻击辱骂。
3. 对一个群体整体下负面结论或套用刻板印象，判为歧视偏见（R4）。用反问、玩梗暗示刻板印象（如“河南抢井盖”）也算；只说“一部分”某群体也算。
4. 评论在质疑、反驳刻板印象（如要求对方“拿出证据”、说“不能一棒子打死”），判为正常（R5）；但反驳时辱骂对方个人，判为攻击辱骂（R2）。
5. 只批评作品、观点、事件本身，没有贬损人的词，判为正常（R1）。

输出要求：
1. 判为违规时，rule_id 填上面对应的编号。如果这个编号不在【可用规则】里，照样填写并照样判违规类别，同时把 confidence 设在 0.6 以下，交给人工复核；不要因为【可用规则】里没有对应规则就判为正常。
2. evidence 从评论中逐字复制最能说明问题的一段，不改写、不拼接、不省略中间的字；判为正常时填空字符串。
3. confidence：证据明确时 0.8 以上；需要靠语气、反讽或上下文推断时 0.6–0.7；拿不准时 0.6 以下。
4. 只输出一个 JSON 对象，不要输出代码块标记或其他文字：
{"label": "...", "rule_id": "R2 或 null", "evidence": "原文片段或空字符串", "confidence": 0 到 1 之间的小数, "reason": "一句话"}

示例（来自开发集）：
评论：这个大鹏太恶心了……电影煎饼侠简直烂到不能算电影吧！这个人非常倒胃口！
输出：{"label": "攻击辱骂", "rule_id": "R2", "evidence": "这个人非常倒胃口", "confidence": 0.8, "reason": "批评作品的同时用贬损词针对具体的人"}
评论：说河南偷井盖的拿出证据呀？
输出：{"label": "正常", "rule_id": "R5", "evidence": "", "confidence": 0.85, "reason": "要求对方为地域刻板印象拿出证据，属于反驳"}
评论：所以你也认为在河南抢井盖不算抢对不对？
输出：{"label": "歧视偏见", "rule_id": "R4", "evidence": "在河南抢井盖不算抢", "confidence": 0.7, "reason": "用反问暗示针对河南人的刻板印象"}
```

## 相对 v1 改了什么、为什么

依据：只看开发集（40 条）上 v1 的结果。v1 错了 8 条，另有 1 条判对但转了人工复核。逐条原因见 `eval/error_notes.csv`。我在知识库检索节点上把这 8 条错例和 e044 逐条重新检索了一遍（e078 未单独查），看召回了哪些规则。

### 开发集 v1 错例归类

| 错因 | 条数 | 例子 | v2 的改法 |
|---|---|---|---|
| 规则不清：针对个人的蔑称、贬损词没被认成辱骂 | 2 | e009“那个狗男人”；e097 批评电影的同时说“这个人非常倒胃口” | 判断步骤第 2 步列出常见贬损词，并写明“批评作品的同时贬损人也算攻击” |
| 规则不清：反讽、反问、玩梗 | 3 | e078 阴阳怪气；e107“在河南抢井盖不算抢对不对？”；e054 用个人经历口吻给性别下结论 | 第 2、3 步写明反讽、反问、玩梗、“一部分某群体”的判法 |
| 例外没写清：反偏见言论被判为歧视 | 1 | e113“说河南偷井盖的拿出证据呀？” | 第 4 步：质疑、反驳刻板印象判为正常（R5），反驳时骂人另算 |
| 检索没召回对应规则，v1 要求“找不到对应规则就判为正常” | 2 | e028、e109 都没召回 R2 | 提示词里补一张规则编号表；没召回时照样判违规类别，置信度压到 0.6 以下，由代码节点的 `rule_not_retrieved` 转人工复核 |
| 证据编造 | 1 | e097 的 evidence 是改写过的，不在原文里 | 输出要求第 2 条：逐字复制，不改写、不拼接、不省略 |
| 规则编号错（引用了没检索到的规则） | 1（未造成判错） | e044 判对了攻击辱骂，但 R2 没被召回，转了人工复核 | 这是检索层面的问题，v2 不改检索，只保证这类样本会进人工复核 |
| 格式问题 | 0 | 40 条都能解析 | 输出要求第 4 条强调不要代码块标记，防止以后出现 |
| 阈值问题 | — | 8 条错例里有 7 条置信度在 0.3–0.6，已经被 0.7 的阈值送进人工复核；只有 e113（0.8）错进了自动标注。自动标注部分准确率 96.9%（31/32） | 阈值保持 0.7 不变 |

### 没有改的

- **知识库规则文本不改**：v1 和 v2 共用同一个知识库，改了规则会同时影响 v1 的测试集结果，两版就没法比了。检索没召回 R2 的问题记在“局限”里。
- **检索参数、代码节点、阈值都不改**：保证 v1 和 v2 只有提示词不同。

### 注意

- 3 个示例直接取自开发集错例（e097、e113、e107），所以 v2 在开发集上的结果对这 3 条不是独立评估，只用来确认改动方向。最终比较以测试集为准，测试集只在 v1、v2 定稿后各跑一次。
